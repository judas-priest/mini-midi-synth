# UI/UX Plan: Mini MIDI Synth

Аудит проведён на основе: исходного кода GUI (egui/eframe), лучших практик UI/UX для синтезаторных плагинов (Voger Design, NN/g, WCAG 2.2, FabFilter/Serum/Vital как эталоны).
Все пункты верифицированы по коду.

---

## 1. Цветовая система: убрать хардкод, ввести палитру

**Проблема:** ~100 вызовов `Color32::from_rgb(...)` разбросаны по 8 файлам. Нет единого источника правды для цветов. Менять тему или проверять контраст — невозможно.

**Верификация:** Подтверждено. `from_rgb`/`from_gray` в: drums.rs(45), keyboard.rs(10), macros.rs(9), layers.rs(11), settings.rs(8), mod.rs(4), params.rs(9), midi_seq.rs(4).

**Контраст:** `from_gray(60)` на `from_gray(30)` — используется для штрихов/линий в pitch sequencer (drums.rs:457,469,488) и разделителей клавиатуры (layers.rs:364). Это **декоративные элементы, не текст** — WCAG требует ≥3:1 для нетекстовых компонентов, фактический контраст ~2:1 — **всё равно FAIL**.

**Практика:** FabFilter, Vital — 2–4 акцентных цвета + нейтральные. Цвета определены в одном месте.

**Действия:**
- [ ] Создать `gui/theme.rs` с константами: `BG_PRIMARY`, `BG_SECONDARY`, `TEXT_PRIMARY`, `TEXT_DIM`, `ACCENT_*`, `PART_COLORS[8]`, `DRUM_COLORS[16]`, `STROKE_DIM` и т.д.
- [ ] Заменить все инлайновые `from_rgb(...)` / `from_gray(...)` на константы из `theme.rs`
- [ ] Поднять `from_gray(60)` штрихи/разделители до `from_gray(90)` минимум (контраст ≥3:1 на фоне gray(30))
- [ ] Поднять `from_gray(50)` step-разделители (drums.rs:469) аналогично

**Приоритет:** высокий
**Сложность:** средняя (много файлов, но механическая замена)

## 2. Тултипы: покрыть все контролы

**Проблема:** Только 8 тултипов на весь интерфейс: Settings(⚙), Help(?), Keybindings(⌨) в топбаре; velocity и Sync BPM в drums; Browse и 2× Mute в midi_seq.

**Верификация:** Подтверждено. 8 вызовов `on_hover_text` на весь GUI. Кнопки Init, Rnd, ◀, ▶ — без тултипов. Все слайдеры params.rs — без тултипов. FX chain, макросы, XY-пад — без тултипов.

**Практика:** FabFilter показывает значение и описание при наведении. Nielsen #1: "система должна информировать пользователя".

**Действия:**
- [ ] Добавить `on_hover_text` ко всем слайдерам в `params.rs`: краткое описание + единица измерения
- [ ] Добавить тултипы к кнопкам Init ("Reset to default patch"), Rnd ("Generate random patch"), ◀/▶ ("Previous/Next preset")
- [ ] Добавить тултипы к табам частей (A1–B4)
- [ ] Добавить тултипы к элементам FX chain
- [ ] Добавить тултипы к макро-ручкам и XY-паду

**Приоритет:** высокий
**Сложность:** средняя (объём работы, но простые правки)

## 3. Значения слайдеров скрыты + нет единиц измерения

**Проблема:** 12 слайдеров явно скрывают значение через `.show_value(false)` (volume, tone, reverb, delay, drum params, layer controls). Только 2 слайдера имеют `.suffix()` — pitch bend ("st") и SF2 offset ("ms"). Все остальные слайдеры — голые числа без единиц.

**Верификация:** Подтверждено. `.show_value(false)`: drums.rs (swing, vol, L, T, D, P), layers.rs (volume, pan), mod.rs (volume, tone, reverb, delay), fx_chain.rs (mix, params). `.suffix()`: только mod.rs:526 ("st") и settings.rs:572 ("ms").

**Практика:** FabFilter — всегда показывает значение + единицы. Стандарт: частота в Hz/kHz, время в ms/s, уровень в dB, % для mix/wet.

**Действия:**
- [ ] Убрать `.show_value(false)` где это скрывает полезное значение (volume, reverb/delay mix, filter params). Оставить скрытым только там, где значение действительно бесполезно
- [ ] Добавить `.suffix("Hz")`, `.suffix("ms")`, `.suffix("dB")`, `.suffix("%")` ко всем слайдерам где уместно
- [ ] Использовать `.custom_formatter` для автоматического переключения Hz↔kHz, ms↔s при больших значениях

**Приоритет:** высокий
**Сложность:** низкая

## 4. Интерактивные паттерны: double-click и fine-tuning

**Проблема:** 0 вызовов `double_clicked()` во всём GUI — нет возможности сбросить параметр в дефолт двойным кликом. egui Slider НЕ поддерживает Shift+drag нативно — тонкая подстройка невозможна.

**Верификация:** Подтверждено. Grep по `double_clicked` — 0 результатов. Grep по `shift`/`fine`/`slow` в контексте слайдеров — 0 результатов.

**Практика:** DAW-стандарт: double-click = reset to default, Ctrl/Shift+drag = fine adjustment.

**Действия:**
- [ ] Добавить обработку `response.double_clicked()` на ключевые слайдеры — сброс к дефолтному значению
- [ ] Исследовать возможность Shift+drag через кастомную логику (проверять `ctx.input(|i| i.modifiers.shift)` и корректировать скорость drag)
- [ ] Документировать доступные жесты в тултипах

**Приоритет:** средний
**Сложность:** средняя

## 5. Визуальная иерархия контролов

**Проблема:** Два размера слайдеров: 250px (дефолт, основной) и 40px (только в drum params). Нет промежуточного — все основные параметры синтеза одного размера. Нет визуального различия между главными (Cutoff, Volume) и второстепенными (Detune, Velocity Curve).

**Верификация:** Подтверждено. `slider_width = 250.0` установлен глобально в mod.rs:360. drums.rs:336 переопределяет на 40.0 локально.

**Практика:** NDSP, FabFilter — главные ручки крупнее, второстепенные мельче. Размер = важность.

**Действия:**
- [ ] Ввести константы в `theme.rs`: `SLIDER_PRIMARY = 250.0`, `SLIDER_SECONDARY = 180.0`, `SLIDER_COMPACT = 120.0`
- [ ] Основные параметры (Cutoff, Resonance, Volume, Mix, Attack, Release) — `SLIDER_PRIMARY`
- [ ] Вспомогательные (Detune, Pan, Velocity Sensitivity) — `SLIDER_SECONDARY`
- [ ] Компактные (Fine Tune, Portamento Time) — `SLIDER_COMPACT`

**Приоритет:** средний
**Сложность:** средняя

## 6. Spacing/layout: систематизировать отступы

**Проблема:** 6 уникальных значений `add_space`: 2.0(×9), 4.0(×79), 5.0(×1), 6.0(×19), 8.0(×11), 12.0(×10). Значение 5.0 — одинокий выброс. Остальные примерно следуют шкале, но не формализованы.

**Верификация:** Подтверждено. Реальное распределение: 4.0 доминирует (79 использований). 5.0 — единственное использование в mod.rs:1078.

**Практика:** Дизайн-системы используют шкалу кратную 4: 4, 8, 12, 16, 24.

**Действия:**
- [ ] Определить spacing scale в `theme.rs`: `SP_XS = 2.0`, `SP_SM = 4.0`, `SP_MD = 8.0`, `SP_LG = 12.0`
- [ ] Заменить `add_space(5.0)` → `SP_SM` (4.0) — убрать выброс
- [ ] Заменить `add_space(6.0)` → `SP_MD` (8.0) или `SP_SM` (4.0) в зависимости от контекста
- [ ] Использовать константы вместо литералов для будущей поддерживаемости

**Приоритет:** низкий
**Сложность:** низкая (механическая замена)

## 7. Визуальное группирование (Gestalt)

**Проблема:** Параметры в params.rs разделены через `ui.strong()` заголовки + `ui.separator()` + `ui.add_space()`. Ни одного `egui::Frame`, `Group` или цветового контейнера. Только 1 `CollapsingHeader` во всём GUI (drums.rs для Step Sequencer).

**Верификация:** Подтверждено. 99 использований strong/separator/add_space в params.rs. 0 Frame/Group wrappers.

**Практика:** Arturia Pigments — colour-coded sections. Vital — секции с фоновыми подложками. Gestalt: common region > proximity.

**Действия:**
- [ ] Обернуть секции (Oscillator, Filter, Envelope, LFO, Modulation) в `egui::Frame` с лёгким фоном (`from_gray(22)` на дефолтном `from_gray(27)`) и скруглёнными углами
- [ ] Добавить тонкие цветные полоски слева от заголовков секций (из палитры `theme.rs`)
- [ ] Убрать избыточные `separator()` где группировка через фрейм уже достаточна

**Приоритет:** средний
**Сложность:** средняя

## 8. Осциллоскоп: слишком мал

**Практика:** Serum, Vital — осциллоскоп минимум ~200×80 px.

- [ ] Или: добавить расширяемый осциллоскоп в центральную панель (кликнуть на маленький → показать большой)

**Приоритет:** низкий
**Сложность:** низкая

## 9. Клавиатура: fixed pad size

**Проблема:** Pad width фиксирован на 32px, не адаптируется к размеру окна. Клавиши адаптивные (key_w clamped 6.0–18.0), а пады — нет. Pad gap = 2px — мало.

**Верификация:** Подтверждено. keyboard.rs:49-50: `pad_size = 32.0`, `pad_gap = 2.0`. Ширина клавиш адаптивная, пады фиксированные.

**Практика:** WCAG 2.5.8: минимум 24×24px (ОК), рекомендация 44×44px.

**Действия:**
- [ ] Сделать `pad_size` адаптивным: `pad_size = (available_width / 10.0).clamp(32.0, 48.0)`
- [ ] Увеличить `pad_gap` до 3–4px

**Приоритет:** низкий
**Сложность:** низкая

## 10. Preset panel: UX улучшения

**Проблема:** Нет индикации позиции в списке. Init/Rnd без тултипов. Навигация ◀/▶ через `small_button` (маленькие). Нет keyboard shortcuts для переключения пресетов.

**Верификация:** Подтверждено. mod.rs:615 — только `"Presets ({layer_label})"`, без индекса. mod.rs:629-638 — Init/Rnd без `on_hover_text`. Keybinds (keybinds.rs:30-48) — F1-F8 (parts), Space/R/Z/X (looper), Tab (drums) — **нет PrevPreset/NextPreset**.

**Практика:** Serum, Alchemy — prev/next с позицией, стрелки для быстрого перебора.

**Действия:**
- [ ] Показать индекс пресета: `format!("Presets ({layer_label}) {}/{}", idx+1, total)`
- [ ] Добавить тултипы: Init, Rnd, ◀, ▶
- [ ] Добавить keybind actions: `PrevPreset`, `NextPreset` в keybinds.rs

**Приоритет:** средний
**Сложность:** низкая

## 11. Undo/Redo для редактирования патчей

**Проблема:** Undo/redo существует ТОЛЬКО для лупера (отмена overdub-слоя, synth/looper.rs:277-292, gui/drums.rs:620-621). Для редактирования параметров патча — undo нет.

**Верификация:** Подтверждено. `undo()` метод только в looper.rs. В params.rs, mod.rs — 0 упоминаний undo.

**Практика:** Phase Plant, все серьёзные DAW — undo/redo обязательны. Nielsen #3: "emergency exit".

**Действия:**
- [ ] Реализовать стек undo для `edited_params`: сохранять снапшот перед каждым изменением (или по группам — один snapshot на "сессию" drag)
- [ ] Ctrl+Z / Ctrl+Shift+Z для undo/redo
- [ ] Показать кнопки undo/redo в тулбаре

**Приоритет:** средний
**Сложность:** высокая (требует архитектурных изменений)

## 12. Loading/status feedback

**Проблема:** Статусные сообщения хранятся как строковые поля (`drum_kit_status`, `perf_status`, `pad_perf_status`) и отображаются как `.weak()` `.small()` текст в панелях. Нет toast/notification системы.

**Верификация:** Подтверждено. 0 результатов по `toast`/`notification`. Статус как label с `.weak()` — легко пропустить.

**Практика:** Toast-нотификации с автоскрытием через 2–3 секунды.

**Действия:**
- [ ] Реализовать простую toast-систему: `Vec<(String, ToastType, Instant)>` + отрисовка + автоскрытие
- [ ] Показывать в фиксированной позиции (bottom-center)
- [ ] Цвет по типу: success = green, error = red, info = blue

**Приоритет:** низкий
**Сложность:** средняя

- [ ] Использовать `.strong()` последовательнее для заголовков секций (уже частично используется)

**Приоритет:** низкий
**Сложность:** низкая
