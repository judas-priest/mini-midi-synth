5. `TopBottomPanel::bottom("pad_perf_bar")` — условно (mod.rs:895-901)

Важные факты:

- **#25 проще, чем предполагал TECHDEBT:** гипотеза «клавиатура рисуется в
  CentralPanel снизу — проверить z/порядок» неверна — клавиатура уже нижняя
  панель. egui 0.31.1 карвит панели по порядку регистрации из
  `ctx.available_rect()` (panel.rs:383): первая зарегистрированная bottom-панель
  = самая нижняя полоса, каждая следующая ложится ВЫШЕ. Значит достаточно
  зарегистрировать `TopBottomPanel::bottom("drum_seq_panel")` ПОСЛЕ
  keyboard_panel и ДО CentralPanel — она встанет ровно между контентом и
  клавиатурой, на всех вкладках.
- **#26: гипотеза TECHDEBT (egui::Window) устарела/неверна.** Панель GM — уже
  `SidePanel::right(...).resizable(true)`, создана ДО CentralPanel (904 < 1197).
  В egui 0.31 панели режут контент по своему rect'у (`panel_ui.set_clip_rect`,
  panel.rs:289), документация: «Always add any CentralPanel last» (panel.rs:14).
  Перекрытия панель-поверх-поля в этой конструкции быть не может. Остаток
  работы: (а) перевести `min_width/max_width` на современный `.width_range`
  (эквивалентно, API 0.31), (б) зафиксировать контракт раскладки headless-тестом
  (egui работает без рендера: `Context::run`, context.rs:802), (в) ручная
  проверка юзером — если перекрытие реально воспроизводится, это поведение
  вне egui-контракта (репорт с скриншотом).
- **#27:** egui-winit 0.31 при отсутствии `ViewportBuilder::title` ставит
  буквально `"egui window"` (egui-winit-0.31.1/src/lib.rs:1632) — совпадает с
  репортом. `with_title` есть в egui 0.31 (viewport.rs:319). `app_id`
  ("mini_midi_synth") не трогаем — это WM_CLASS на X11/Wayland, менять нельзя
  (eframe-персистенция и оконный менеджер по нему).
- `draw_drum_sequencer` (gui/drums.rs:14-377) — единственный вызов mod.rs:1213.
  Внутри: транспорт-строка (Play/Rec/флеш-даунбит/Undo/Clear **+ BPM/Swing/Vol/
  V127/Metro в той же строке**, drums.rs:21-96), кнопка Remap (98-103), выбор
  паттерна 1-8 + Steps (105-123), Kit Save/Load (125-189), MIDI-импорт
  (191-224), сетка 16×16 с per-slot слайдерами L/T/D/P в строках (228-376).
  Слайдеры приклеены к строкам сетки — уезжают вместе с сеткой.
  `draw_drum_remap_modals` уже глобальна (вызов из update, mod.rs:1194;
  TECHDEBT #11) — перенос кнопки Remap её не ломает.

**Дизайн-решение по #25 (зафиксировано):** докуется «сетка + транспорт»
(Play/Stop, Rec, флеш, Undo, Clear, выбор паттерна, Steps, сетка с per-slot
слайдерами). На вкладке Drums остаются BPM, Swing, Vol, V127, Metro, Remap,
Kit Save/Load, MIDI-импорт (как предписано в постановке задачи). Сетка всегда
видима на всех вкладках — это и есть заявка юзера; вкладка Drums превращается
в «микшер/киты ударки».

**Tech Stack:** только egui 0.31 API (уже в дереве), никаких новых зависимостей.
Тест раскладки — `eframe::egui::Context::run` headless (без GPU/окна), идёт в
`cargo test` (feature `gui` — default).

**Spec context:** docs/TECHDEBT.md #25, #26, #27.

## Test Cases (from the requirement)

Требование #25 (панель всегда снизу, над клавиатурой/пэдами, на любой вкладке):
1. Вкладка Synth (дефолт) → сетка секвенсора видна внизу окна, МЕЖДУ основным
   полем и GUI-клавиатурой/пэдами (юнит: contract-тест
   `panels_carve_no_overlap_seq_above_keyboard`).
2. Переключение вкладок Drums / MIDI Seq / FX / Synth → панель остаётся на
   месте, содержимое основного поля меняется (ручной).
3. Кнопки Play/Rec/Undo/Clear, выбор паттерна и клики по сетке работают с
   любой вкладки; playhead бежит (ручной).
4. Drums-вкладка: BPM/Swing/Vol/V127/Metro/Remap/Kit/MIDI-импорт доступны;
   BPM меняется → playhead ускоряется (ручной).
5. Клик по GUI-пэду открывает remap-модалку ПОВЕРХ докованной панели
   (ручной; модалки глобальны с #11).
6. Ресайз панели мышью (тянуть верхнюю кромку) — сетка скроллится внутри
   панели, клавиатура не уезжает; размер переживает рестарт (ручной).

Требование #26 (ресайз правой панели сжимает основное поле):
7. Контракт: central.max_x ≤ gm.min_x и при расширении GM-панели на 100px
   основной край сжимается ровно на 100px (юнит: `gm_panel_resize_reflows_central`).
8. Порядок «панели до CentralPanel» — панели не пересекаются (юнит:
   `panels_carve_no_overlap_seq_above_keyboard`).
9. Ручной: тянуть разделитель GM-панели — основное поле пере-позиционируется,
   ничего не перекрыто; то же на вкладках Drums/MIDI Seq и в SF2-режиме.

Требование #27 (заголовок окна):
10. `ViewportBuilder::with_title("Mini MIDI Synth")` в desktop-ветке lib.rs
    (юнит-теста нет — заголовок устанавливает ОС; MANUAL CHECKLIST).
11. app_id остаётся "mini_midi_synth" (Wayland/X11 класс не меняется).

### Negative Matrix (ручной, разом в Task 4)

- Минимальное окно (min 500×300): докованная панель сжимается, сетка
  скроллится внутри неё (ScrollArea в панели), клавиатура видна, приложение
  не падает.
- Широкая GM-панель (до 260px) + узкое окно 500px: центральное поле ≥ ~240px,
  контент скроллится, ничего не перекрыто.
- PAD PERF-индикатор вкл (модальный тумблер): жёлтая строка между секвенсором
  и клавиатурой, обе панели видны.
- MIDI Learn-режим: верхняя строка появляется, докованная панель не дёргается.
- Тосты («Kit saved»): по-прежнему у нижней кромки (якорь к окну, не к панели).
- Открытые окна Settings/Keybindings/PadPerf: поверх всего, не вытесняют панели.
- Рестарт приложения: ширина GM-панели и высота секвенсорной панели
  восстанавливаются (egui persist, `persist_window: true`).
- Keybind ToggleDrumsSynth: тоглится только содержимое Drums-вкладки
  (микшер/киты), сетка снизу не исчезает — осознанное изменение поведения
  (раньше спрятывалась вся панель; требование #25 — «всегда»).

  //! Layout-contract tests for the egui panel registration order
  //! (TECHDEBT #25/#26). egui runs headless here: `Context::run` computes
  //! layout without a renderer or window.
  //!
  //! NOTE (egui 0.31): panels COLLAPSE TO CONTENT unless the content fills
  //! them — a `TopBottomPanel` frame shrinks to `height_range.min` and a
  //! `SidePanel` frame to its width_range.min if the content is tiny. The
  //! docked panels here use ScrollArea::auto_shrink(false) exactly like the
  //! real mod.rs code, otherwise geometry differs from production.
  //!
  //! This test MIRRORS the panel registration order of
  //! `src/gui/mod.rs::update` (top panels omitted — irrelevant to the
  //! bottom/right carving). If you reorder panels in mod.rs, update this
  //! mirror.
  #![cfg(feature = "gui")]

  use eframe::egui;

  const WIN: (f32, f32) = (1024.0, 640.0);

  /// One headless frame with the same panel registration order as mod.rs.
  /// `gm_width` pins the right panel width (exact_width bypasses the
  /// resizable drag state so the assertion is deterministic).
  fn frame(gm_width: f32) -> (egui::Rect, egui::Rect, egui::Rect, egui::Rect) {
      // (keyboard, drum_seq, gm_panel, central)
      let ctx = egui::Context::default();
      ctx.set_pixels_per_point(1.0);
      let input = egui::RawInput {
          screen_rect: Some(egui::Rect::from_min_size(
              egui::Pos2::ZERO,
              egui::vec2(WIN.0, WIN.1),
          )),
          ..Default::default()
      };
      let mut rects = None;
      // `Context::run` is #[must_use] — FullOutput not needed, rects captured
      let _ = ctx.run(input, |ctx| {
          // -- mirrors mod.rs: keyboard first (bottom-most), then the docked
          //    drum sequencer, then the right panel, CentralPanel LAST.
          let kb = egui::TopBottomPanel::bottom("keyboard_panel")
              .exact_height(90.0)
              .show(ctx, |ui| {
                  ui.label("kb");
              });
          let seq = egui::TopBottomPanel::bottom("drum_seq_panel")
              .resizable(true)
              .default_height(460.0)
              .height_range(120.0..=640.0)
              .show(ctx, |ui| {
                  // auto_shrink(false) fills the panel — same as mod.rs
                  egui::ScrollArea::vertical().auto_shrink(false).show(ui, |ui| {
                      ui.label("seq");
                  });
              });
          let gm = egui::SidePanel::right("preset_panel")
              .resizable(true)
              .exact_width(gm_width)
              .width_range(120.0..=260.0)
              .show(ctx, |ui| {
                  egui::ScrollArea::vertical().auto_shrink(false).show(ui, |ui| {
                      ui.label("gm");
                  });
              });
          let central = egui::CentralPanel::default().show(ctx, |ui| {
              ui.label("main");
          });
          rects = Some((
              kb.response.rect,
              seq.response.rect,
              gm.response.rect,
              central.response.rect,
          ));
      });
      rects.expect("ui closure must run")
  }

  /// #25/#26 contract: panels carve in registration order; the docked drum
  /// sequencer sits ABOVE the keyboard strip and BELOW the central field;
  /// nothing overlaps.
  #[test]
  fn panels_carve_no_overlap_seq_above_keyboard() {
      let (kb, seq, gm, central) = frame(160.0);

      // keyboard pinned to the very bottom
      assert!((kb.max.y - WIN.1).abs() < 0.5, "keyboard not at bottom: {kb:?}");
      // sequencer stacked directly on top of the keyboard
      assert!(
          (seq.max.y - kb.min.y).abs() < 0.5,
          "seq must sit directly above keyboard: seq={seq:?} kb={kb:?}"
      );
      // default height honored
      assert!((seq.height() - 460.0).abs() < 0.5, "seq height: {seq:?}");
      // central field ends where the sequencer begins
      assert!(
          (central.max.y - seq.min.y).abs() < 0.5,
          "central must end above the seq panel: {central:?} vs {seq:?}"
      );
      // the right panel is carved AFTER the bottom panels: top..seq_top only
      assert!(
          (gm.max.y - seq.min.y).abs() < 0.5 && gm.min.y.abs() < 0.5,
          "gm panel must span top..seq_top: {gm:?}"
      );
      // central strictly left of the right panel (touching edge == reflow)
      assert!(
          central.max.x <= gm.min.x + 0.5,
          "central overlaps gm: {central:?} vs {gm:?}"
      );
  }

  /// #26 contract: widening the GM panel shrinks the main field by the same
  /// amount instead of overlapping it.
  #[test]
  fn gm_panel_resize_reflows_central() {
      let (_, _, gm, central) = frame(160.0);
      let (_, _, gm_wide, central_wide) = frame(260.0);

      assert!((gm.width() - 160.0).abs() < 0.5);
      assert!((gm_wide.width() - 260.0).abs() < 0.5);

      // central strictly to the left of the panel in both cases
      assert!(
          central.max.x <= gm.min.x + 0.5,
          "central overlaps gm: {central:?} vs {gm:?}"
      );
      assert!(
          central_wide.max.x <= gm_wide.min.x + 0.5,
          "central overlaps gm: {central_wide:?} vs {gm_wide:?}"
      );
      // reflow, not overlap: +100 px of panel == -100 px of central width
      let d_gm = gm_wide.width() - gm.width();
      let d_c = central.width() - central_wide.width();
      assert!(
          (d_gm - d_c).abs() < 0.5,
          "central must reflow 1:1 with panel resize: dg={d_gm} dc={d_c}"
      );
  }

  (`--no-default-features`) тест не компилирует — `#![cfg(feature = "gui")]`.

  КОНТЕНТУ — фрейм bottom-панели сжимается до `height_range.min`, фрейм
  side-панели — до `width_range.min`, если контент крошечный. Поэтому контент
  обеих докованных панелей в тесте (и в mod.rs) обязан быть
  `ScrollArea::auto_shrink(false)` — он растягивается на всю панель. Тест
