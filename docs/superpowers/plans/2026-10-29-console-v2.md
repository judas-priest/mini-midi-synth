# LED Console v2: Transport Target + Mute Paging + Drum Redo Implementation Plan

anchor-checked: 2026-10-29 (якоря сняты с master @ ecf67e7 чтением кода в этой сессии)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Три фичи консоли v2 (бэклог techdebt #15): (1) 4-й пункт меню (слот 3) —
переключатель «нижняя строка слушает: драм-секвенсор / лупер» — это существующий
`seq_target`; пэд-транспорт 25/26/27 (ноты 82/81/83) унифицирован с Seq-кнопками
123/124 и следует за целью; нижняя LED-строка показывает состояние активной цели.
(2) MUTE-режим разбит на страницы по 7 частей (симметрично перф/паттерн-окнам) —
зона B и хвостовые части доступны с пэдов. (3) Redo драм-секвенсора: холд пэда 32
(≥500 ms) = redo, тап = undo; пэд 32 белеет (FFFFFF), когда redo доступен.

**Architecture:**
- `seq_target` — атом `AtomicU8` в движке (`src/synth/mod.rs:1183`, дефолт 1 =
  looper), GUI меняет его ПРЯМЫМ store (ControlEvent не существует — движок читает
  атом в `handle_event`). Слоты 123/124 уже следуют цели (`synth/mod.rs:1729-1750`);
  ноты 81/82/83 (пэды 26/25/27) сейчас захардкожены на драмы и, что хуже, сидят
  ВНУТРИ ветки `channel == 9 || (is_drum_note && drum_mode)` — при target=1
  (looper) вся ветка не выполняется и пэды мертвы. Фикс: 82 слить с arm 123,
  83 — с arm 124, 81 вынести наружу ветки.
- MUTE-страницы: окно `App.mute_window` (0..=9) по образцу `perf_window`/`pat_window`;
  PAGE-пэды 28/29 уже mode-aware (`page_window`, gui/mod.rs:1939) — добавляется arm
  `Mode::Mute`. `top_colors` получает `mutes: &[bool]` (все 16 частей) + `w_mute`.
- Redo: `StepSequencer.redo_snapshot: Option<Box<[DrumPattern; MAX_PATTERNS]>>`
  + `redo_atom` (один уровень, тот же Box-паттерн что `undo_snapshot`).
  Триггер — холд пэда 32: `PadEvent::Undo` (fire-on-NoteOn) заменяется на
  `UndoDown`/`UndoUp` (note 75 on/off — midi.rs уже шлёт оба, `is_console_note`
  покрывает 75..=80); релиз < HOLD = Undo, ≥ HOLD = Redo. `tick()`-меню-холд не
  задет: `undo_down` не регистрируется в top-row `pending`.
- RT-safety: из аудиопотока — только атомарные store/load; единственные
  alloc/free (Box снимков в `undo`/`redo`) живут в `handle_control` — тот же
  класс существующего долга, что `DrumSeqClear`/`DrumSeqUndo` (Box::new +
  drop там уже есть); rt-assert тест на redo НЕ добавляем (упал бы на alloc,
  как и упал бы на существующий undo — долг документирован, не расширяем).

**Tech Stack:** Rust, egui, rtrb/AtomicU8/AtomicBool — без новых зависимостей.

**Spec context:** docs/superpowers/specs/2026-10-29-bank2-led-console-design.md;

## Test Cases (from the requirement)

Feature 1 (transport target):
1. Тап слота 3 в Menu → `Action::ToggleTransportTarget`, режим Menu СОХРАНЯЕТСЯ
   (это toggle, а не вход в режим).
2. LED слота 3 в Menu: синий 0066FF при target=0 (драмы), зелёный 00FF00 при
   target=1 (лупер) — оба цвета из validated-палитры.
3. Нота 82 ch9 (пэд 25) при target=0 → toggle `drum_engine.sequencer.playing`
   (+reset позиции на стоп — семантика кнопки 123); при target=1 → `looper.toggle_play()`.
4. Нота 83 ch9 (пэд 27) при target=0 → toggle записи драм (+auto-play как пэд-путь
   сегодня); при target=1 → `looper.toggle_record()`.
5. Нота 81 ch9 (пэд 26) при target=0 → стоп+reset драм; при target=1 → стоп лупера
   ТОЛЬКО если он играл (Idle не должен начать играть).
6. Нижняя LED-строка при target=1 показывает состояние ЛУПЕРА: зелёный при
   Playing/Overdubbing, красный при Recording/Overdubbing, жёлтый Stop при Idle.
7. Негатив: ноты 82/83 на НЕ-ch9 (обычная клавиатура) играют ноты, транспорт не
   трогают; нота 81 при target=1 и Idle лупере — no-op.

Feature 2 (mute paging):
8. Слот i (1..=7) в MUTE показывает часть `w_mute + i - 1`: звучащая = зелёный,
   приглушённая = OFF, за концом списка = OFF.
9. PAGE◀/PAGE▶ в MUTE двигают `mute_window` на 7 с clamp в [0, parts-7].
10. Тап слота мьютит РЕАЛЬНУЮ часть `mute_window + i - 1` (GUI-маппинг, как
    LoadPerf: `perf_window + i - 1`).
11. Негатив: окно 0 + PAGE◀ → остаётся 0; окно max + PAGE▶ → остаётся max;
    пустой parts (недостижимо, parts всегда 16) → `.get()` → OFF.

Feature 3 (redo):
12. undo→redo roundtrip: запись → snapshot/undo → паттерны пустые → redo →
    паттерны вернулись; undo снова доступен.
13. redo без предыдущего undo → no-op (паттерны не меняются, атом false).
14. Новая деструктивная операция (save_snapshot/clear_pattern) инвалидирует redo.
15. Пэд 32: тап (< 500 ms) = Undo; холд (≥ 500 ms) с релизом = Redo; холд пэда 32
    НЕ открывает меню (tick во время hold возвращает None); stray UndoUp без Down
    = no-op.
16. LED пэда 32: redo доступен → белый FFFFFF (приоритет), иначе undo → розовый
    FF5080, иначе OFF.

## Negative Matrix

- Слот 3 тап в Menu при повторном тапе — toggle туда-обратно, mode не улетает
  (тест menu stays Menu).
- Ноты 123/124 на других каналах по-прежнему работают (условие `channel == 9`
  только для 81/82/83).
- Лупер Idle + нота 82 → `toggle_play()` с `len == 0` — внутри no-op
  (looper.rs:273 гейт `self.len > 0`), тест фиксирует отсутствие паники.
- `mutes.get(idx)` при idx за концом — None → OFF (не паникует на срезе).
- double-NoteOn на 75 (повтор NoteOn без NoteOff) — `undo_down` просто
  перезаписывается временем последнего Down (последний hold выигрывает).
- UndoDown без последующего UndoUp (потерян NoteOff, BT) — пэд «залип» в hold;
  следующий NoteOn перезапишет `undo_down`, LED не врёт (снимок пересчитывается
  каждый кадр). Ручная проверка в Task 6.
- redo_atom при пересборке движка (audio reconnect) — свежий false; GUI перевwitch
  в settings.rs:251-паттерне.
- clock skew — неприменимо (Instant монотонный).
- concurrent console events — GUI-поток один, mpsc сериализует.

```rust
            MidiEvent::NoteOn { channel, note, velocity } => {
                // SMK-37 Pro transport, unified: SEQ buttons (any channel,
                // notes 123/124) and bank-2 pads ch9 (82 = pad 25 play,
                // 83 = pad 27 rec) follow seq_target. Stop (81, pad 26) arm
                // below. Pad notes must not fall into the trigger path.
                if velocity > 0 && (note == 123 || (channel == 9 && note == 82)) {
                    let target = self.seq_target.load(std::sync::atomic::Ordering::Relaxed);
                    if target == 0 {
                        // Drums mode
                        let seq = &mut self.drum_engine.sequencer;
                        seq.playing = !seq.playing;
                        if !seq.playing { seq.reset(); }
                    } else {
                        // Looper mode
                        self.looper.toggle_play();
                    }
                    return;
                }
                if velocity > 0 && (note == 124 || (channel == 9 && note == 83)) {
                    let target = self.seq_target.load(std::sync::atomic::Ordering::Relaxed);
                    if target == 0 {
                        // set_recording snapshots (undoable) — same path as
                        // DrumSeqRecord / pad 27 before the unification.
                        let rec = !self.drum_engine.sequencer.recording;
                        self.drum_engine.set_recording(rec);
                        if rec && !self.drum_engine.sequencer.playing {
                            self.drum_engine.set_playing(true);
                        }
                    } else {
                        self.looper.toggle_record();
                    }
                    return;
                }
                // Pad 26 (note 81, ch9): stop — outside the drum-note gate so
                // it works at seq_target=1 (looper) too.
                if channel == 9 && velocity > 0 && note == 81 {
                    if self.seq_target.load(std::sync::atomic::Ordering::Relaxed) == 0 {
                        self.drum_engine.set_playing(false);
                        self.drum_engine.sequencer.reset();
                    } else if matches!(self.looper.state,
                                       crate::synth::looper::LooperState::Playing
                                       | crate::synth::looper::LooperState::Overdubbing) {
                        self.looper.toggle_play();
                    }
                    return;
                }
```

```rust
    /// Redo the last undone destructive op (single level, same Box pattern as
    /// undo_snapshot). undo() pushes the pre-restore state here; redo() swaps
    /// it back and re-arms undo.
    pub fn redo(&mut self) {
        if let Some(snapshot) = self.redo_snapshot.take() {
            self.undo_snapshot = Some(Box::new(self.patterns));
            self.patterns = *snapshot;
        }
        self.sync_undo_atom();
        self.sync_redo_atom();
    }

    /// A new destructive op invalidates redo: the saved state is stale and
    /// redoing it would resurrect patterns the user has since replaced.
    pub fn cancel_redo(&mut self) {
        self.redo_snapshot = None;
        self.sync_redo_atom();
    }

    fn sync_redo_atom(&self) {
        self.redo_atom.store(self.redo_snapshot.is_some(), Ordering::Relaxed);
    }

    pub fn redo_atom(&self) -> Arc<AtomicBool> {
        self.redo_atom.clone()
    }

    pub fn redo_available(&self) -> bool {
        self.redo_atom.load(Ordering::Relaxed)
    }
```
