# Банк-2 пэдов SMK-37 Pro как динамическая LED-панель управления

Дата: 2026-10-29. Статус: утверждена пользователем.
Связанное: techdebt #13 (драм-консоль), #14 (синт-консоль), #15 (LED-меню, эксперименты).

## Цель

Банк-2 пэдов клавиатуры становится аппаратным пультом синта: нижняя строка —
глобальный транспорт, верхняя — контекстные действия с LED-подсветкой состояния
(Launchpad-style). Играешь — видишь состояние на клаве, мышью не пользуешься.

## Аппаратная база (эксперименты 2026-10-28, см. smk37_config/PADS_NOTES.md)

- LED красится записью color-слота по GATT AE40 **без commit** — LED живёт в RAM,
  мгновенно (8 пэдов ≈ 5 ms), flash не изнашивается, power-cycle откатывает к
  сохранённой раскладке. Постоянная раскладка = отдельные commit'ы.
- MIDI-SysEx LED-канала в stock FW нет — краска только через GATT → нужен
  компаньон-процесс с BLE-клиентом.
- Ноты пэдов банка 2 перепрошиваются через конфиг-слоты (smk.py), постоянные.

## Раскладка

Нижняя строка (пэды 25–32) — фиксирована во всех режимах, по маркировке корпуса:

| Пэд | Нота (ch9) | Действие | LED |
|-----|------------|----------|-----|
| 25 | 82 | Play/Pause секвенсора (цель по seq_target: ударка/лупер) | зелёный играет / тускло-серый нет |
| 26 | 81 | Stop (позиция в начало) | жёлтый на стопе |
| 27 | 83 | Record (в активный паттерн) | красный пишет / тускло-серый |
| 28 | 80 | Rew: лупер в начало | тускло-янтарный |
| 29 | — | не задействован (v1) | тёмный |
| 30 | 78 | Prev: перф−1 (HOME) / паттерн−1 (PATTERN) | тускло-серый |
| 31 | 79 | Next: перф+1 / паттерн+1 | тускло-серый |
| 32 | 64 | Undo секвенсора | тускло-серый |

Ноты 81/82/83/64 уже маршрутизируются движком (mod.rs:1573-1598) — v1 только
перепрошивает ноты пэдов на них и добавляет 78/79/80.

Верхняя строка (пэды 17–24, ноты 60–67 ch9):

- **HOME (дефолт)**: 8 пэдов = перформанс-слоты 1–8. Ярко горит активный,
  тускло — заполненные, тёмный — пустые. Тап = мгновенная загрузка перформанса.
- **PATTERN**: 8 пэдов = паттерны 1–8, горит играющий. Тап = переключение
  (квантирование по такту — будущая опция, v1 мгновенно).
- **MUTE**: 8 пэдов = мьюты частей 1–8 (зона A). Приглушённая часть — тёмный пэд,
  звучащая — цвет категории части.
- **Меню**: холд любого пэда верхней строки ≥500 ms → строка перекрашивается в
  меню: 17 = HOME, 18 = PATTERN, 19 = MUTE (белые тускло), 20–24 тёмные.
  Тап по пункту = вход в режим. Повторный холд → снова меню.

Тап/холд: NoteOn запоминает время; NoteOff до 500 ms = тап; таймер 500 ms без
NoteOff = холд. Реализация — GUI-поток, чистая логика.

Физические кнопки: Seq Play (note 123) / Seq Rec (124) — уже работают как
транспорт с переключателем цели (seq_target: ударка/лупер); нашими пэдами не дублируются, одновременная работа допустима. Стрелки < > — одинаковый SysEx (не различить),
не используются. Кнопки Octave/Bank MIDI не шлют.

## Архитектура

Три компонента, границы по данным:

1. **Консоль-автомат** (`src/gui/led_console.rs`, чистая логика, unit-тесты):
   вход — события пэдов (Tap(slot), Hold, NoteOn/NoteOff c таймером) и текущее
   состояние синта (активный перф, играющий паттерн, мьюты, транспорт);
   выход — команды (загрузить перф, выбрать паттерн, мьют, undo...) и
   LED-снимок (16 цветов RRGGBB). Не знает ни про BLE, ни про MIDI-тред.

2. **Синт-интеграция** (`src/gui/`): MIDI-тред midir зеркалит ноты 60–67/78–80
   ch9 в GUI-канал (std mpsc) и НЕ кладёт их в аудио-кольцо (ударка их не
   слышит). GUI-поток гонит их в автомат; команды автомата выполняет
   существующими ControlEvent'ами (DrumSeqPattern/Undo, SetPartMute) и
   `load_performance_by_name`. Настройка `led_companion: bool` в UiSettings
   (дефолт off) — при off синт не подключается к сокету и LED не трогает.

3. **Компаньон** (`~/Projects/smk37_config/pad_console.py`, Python, реюз
   проверенной логики smk.py — ноль новых зависимостей в репо синта):
   слушает unix-сокет `/tmp/mini_midi_synth_led.sock`; синт — клиент, шлёт
   текстовые строки `STATE <16×RRGGBB через пробел>` при каждом изменении.
   Компаньон маппит слот 0–7 → пэды 17–24 (адрес 1467+74*(p−17)),
   слот 8–15 → пэды 25–32 (2059+74*(p−25)), пишет 4 байта RRGGBB+FF без
   commit (framing/checksum — как в smk.py: header 00 59, cmd 0x22,
   checksum ~sum(payload)). BLE-reconnect автоматически. Запускается
   пользователем вручную; умер компаньон / сокета нет — синт работает,
   LED просто не меняется. (Rust+bluer отклонён: лишние deps в аудио-репо;
   путь к Rust-компаньону остаётся открытым, если python не приживётся.)

Один BLE-центр: при работающем компаньоне телефонный MidiSuite не подключён
(документированное ограничение).

## Палитра

| Назначение | RGB |
|------------|-----|
| Меню-пункты (HOME/PATTERN/MUTE в меню) | 404040 |
| Активный перформанс / играющий паттерн | FF8000 |
| Заполненный перф / текущий паттерн (неактивный) | 303030 |
| Пустой слот | 000000 (флаг FF, LED off) |
| Часть звучит (MUTE-режим) | 0066FF |
| Часть приглушена | 101010 |
| Play горит / не горит | 00FF00 / 202020 |
| Rec горит / не горит | FF0000 / 202020 |
| Стоп / вспомогательные | FFDD00 / 202020 |

## Не в v1

Квантованное переключение паттернов/перформансов, режим SCENE (extra), Redo,
афтертач-модуляция, дисплей клавиатуры (только кастомная FW: Snoop37/FM1 Open),
мастер-транспорт «секв+лупер синхронно» (сохраняем существующий seq_target).

## Риски

- Компаньон на python/sm-k — протокол проверен (smk.py), GATT через BlueZ DBus.
  Риск низкий: верификация чтением назад после записи.
- Перепрошивка нот пэдов — постоянная (commit): делать полной записью
  74-байтовых рекордов, верифицировать чтением (уроки PADS_NOTES.md).
